# Testing Rules (PART 28, 29, 30)

⚠️ **These rules are NON-NEGOTIABLE. Violations are bugs.** ⚠️

<!-- Rule summary checked against AI.md on 2026-10-17; AI.md remains authoritative. -->

## CRITICAL - NEVER DO

- Never run binaries, `go build`, or `go test` directly on the local machine — no Go is installed locally, ALL builds/tests run in Docker (`casjaysdev/go:latest`) or Incus
- Never use project-directory paths (`./volumes/`, `./docker/rootfs/`) for runtime/test mounts — pollutes the repo; use `/tmp/{project_org}/{internal_name}-XXXXXX/volumes/`
- Never use bare `/tmp` or bare `mktemp -d` — always `/tmp/{project_org}/{internal_name}-XXXXXX/` with org+project+random structure
- Never run `docker compose up` with `docker-compose.yml` or `docker-compose.dev.yml` as AI — those are human-only; AI uses `docker-compose.test.yml` via `tests/` scripts only
- Never use `pkill -f`, `pkill {name}` (no `-x`), `killall`, `kill -9` first, or any broad `docker rm/rmi/system prune` — only exact PID/name/tag, scoped to `{project_name}`
- Never put non-ReadTheDocs files in `docs/` — it is ONLY for MkDocs documentation (source → `src/`, scripts → `scripts/`)
- Never hardcode user-facing strings anywhere (web, API, Swagger, GraphQL, email, CLI, agent output) — every string MUST use a translation key, no exceptions
- Never let translation files diverge — every key in `en.json` MUST exist in all other language files (build-time enforced)
- Never error/crash on unsupported `--lang`/`Accept-Language`/`?lang=` — silently fall back to `en`
- Never convey information by color alone (accessibility) — pair color with icon/text
- Never skip Phase 1 (`make test`, ≥60% coverage) as a pre-commit gate — it is required before every commit
- Never run the Browser E2E suite (`tests/e2e.sh`) as, or block on it in, the commit gate — `make test` never runs it; a feature passing only Tier 3 (full JS) is a progressive-enhancement violation, not a pass
- Never treat an AI-driven exploratory browser pass as a gate — it is discovery only; confirmed findings must become committed deterministic chromedp tests or `TODO.AI.md` entries

## CRITICAL - ALWAYS DO

- Always run host-affecting test steps (systemd, iptables, mount, reboot, package install) inside Docker/Incus/VM — never on the host (Host System Safety Rule, PART 0, applies to all testing)
- Always maintain both test phases: Phase 1 Toolchain Gate (`*_test.go` via `make test`, ≥60% coverage, pre-commit) and Phase 2 Binary Validation (`./tests/*.sh`, 100% endpoint coverage, manual/developer-initiated)
- Always create/update the matching `*_test.go` in the same work pass when adding/changing package logic — never defer to the end
- Always test every route with ALL applicable Accept headers: frontend routes get `text/html` + `text/plain`; API routes get `application/json` + `text/plain`; every `.txt` endpoint tested directly
- Always provide `tests/run_tests.sh` (auto-detect), `tests/docker.sh` (Alpine fallback), `tests/incus.sh` (Debian+systemd, preferred), and `tests/e2e.sh` (headless-browser beta testing) — executable, `set -eo pipefail`, `trap` cleanup, WTFPL header (`# @@License : WTFPL`)
- Always prefer Incus (`images:debian/trixie`, full systemd) for integration testing; fall back to Docker (`casjaysdev/go:latest` build, `alpine:latest` run) when Incus unavailable
- Always host-mount `GO_CACHE`/`GO_BUILD` cache dirs for Docker Go builds, and build via `make build` when a Makefile exists (output always `binaries/`)
- Always include the required `docs/` files (`index.md`, `installation.md`, `configuration.md`, `api.md`, `security.md`, `integrations.md`, `development.md`, `requirements.txt`; `cli.md` if applicable) plus root `mkdocs.yml` and `.readthedocs.yaml`
- Always support all 7 required languages identically across server and CLI binaries (single `src/common/i18n/locales/` embedded via `go:embed`)
- Always meet WCAG 2.1 AA: 4.5:1 text contrast, full keyboard navigation, screen-reader support, visible focus indicators, 44×44px touch targets, skip links as first focusable elements
- Always run all three Browser E2E tiers (SSR, no-JS browser, full browser) when the E2E suite runs, covering every IDEA.md feature and the universal checklist (full crawl, owner-token flows, docs pages, theme, responsive, i18n, forms/CSRF, error pages, static assets, zero console errors)

## Key Rules Summary

**Containerized testing (Docker/Incus):** Local machine has no Go — building/testing/running binaries ALWAYS happens in a container. Two container types: Docker `casjaysdev/go:latest` for building and quick Alpine tests (CI/CD, ~1s startup); Incus `debian:latest` for full OS/systemd tests (service install, integration, ~5s startup). `docker-compose.test.yml` is the only compose file AI may use, and only via `tests/` scripts (fallback: copy to a `/tmp/{project_org}/{internal_name}-XXXXXX/` temp dir and run directly).

**Temp directory structure:** ALL runtime/test data uses `{tempdir}/{project_org}/{internal_name}-XXXXXX/` (e.g. `/tmp/apimgr/vidveil-aB3xY9/`) — never bare `/tmp`, never a generic path, never missing the org prefix. `volumes/config` and `volumes/data` subdirs for compose-style test runs. E2E failure artifacts (screenshots, page HTML, server log) also go here, never the project tree. Clean up with `rm -rf "${TMPDIR:-/tmp}/${PROJECT_ORG}/"`.

**Test file conventions:** `*_test.go` (Go `go test`, package logic, functions, validation, mocks/httptest — proves ≥60% code coverage) vs `./tests/*.sh` (running binary, real HTTP/process/container behavior — proves 100% endpoint coverage). One does not replace the other. Required scripts under `tests/`: `run_tests.sh`, `docker.sh`, `incus.sh`, `e2e.sh` (all executable, WTFPL-licensed `# @@License : WTFPL` header). `run_tests.sh`/`docker.sh`/`incus.sh` build via `make build` (or raw `docker run casjaysdev/go:latest go build` fallback), install `curl bash file jq` in the test container, start the server, run version/help/binary-info checks, **binary rename tests** (copy + rename, verify `--help` shows new name), operator-token setup (read `server.token` from `server.yml`), content-negotiation tests, frontend smart-detection tests, project-specific endpoint tests from IDEA.md, and CLI full-functionality tests against the running server. Additional helper scripts (e.g. `tests/test_content_negotiation.sh`) are allowed and complement, never replace, `*_test.go`.

**Browser E2E testing (`tests/e2e.sh`, on-demand, NOT a commit gate):** Engine `github.com/chromedp/chromedp` driving headless Chromium over CDP — pure Go, no Node toolchain. Test code lives in `tests/e2e/` behind the `e2e` build tag so `make test` never runs it; `tests/e2e.sh` Docker-wraps `go test -tags e2e ./tests/e2e/...`, joining the manual `./tests/*.sh` family. No new Makefile target (the six-target set is fixed). Three mandatory tiers, ALL required: Tier 1 SSR (plain `net/http`, no browser — real content in initial HTML, correct title/meta, never an empty JS-filled shell), Tier 2 no-JS browser (chromedp with script execution disabled — progressive-enhancement flows: form POSTs, links, redirects, pagination), Tier 3 full browser (chromedp with JS on — full enhanced flows, zero console errors, zero failed asset/XHR requests). A feature passing only Tier 3 is a progressive-enhancement violation. Coverage required: project-scoped IDEA.md features (each gets ≥1 scenario per tier) plus universal checks — full link crawl (no dead links/500s), owner-token create/edit/delete plus reveal/rotate/linked-token/restore management and MCP authorization flows, Swagger/GraphiQL docs pages match real routes, theme (dark/light/auto computed-style changes), responsive (375×812, no horizontal scroll), i18n string switching, form validation + CSRF, themed 404/500 pages, all static assets 200, zero JS console errors. Must be deterministic and hermetic: fresh seeded test DB, zero external network (webhooks/GeoIP/update-checks stubbed via local `httptest`), server on a port from 64000-64999, PID captured and killed in teardown. Run on demand (beta testing, pre-release, after major frontend work); in CI at most a manual `workflow_dispatch` job, never a required check. AI-driven exploratory browser passes (e.g. Playwright MCP) are discovery-only, never a gate — every finding is fixed or logged to `TODO.AI.md`, and every confirmed finding becomes a committed deterministic chromedp test.

**Coverage requirements:** Phase 1 ≥60% via `go test -cover` (enforced in CI, fails build below 60%); Phase 2 100% endpoint/route coverage including error paths (400/401/403/404/500) and edge cases. Priority: always test auth/token validation, DB queries/migrations, API handlers; best-effort simple getters/logging; skip third-party internals.

**Process/cleanup discipline:** identify exact PID/container/image before any kill/remove; graceful `kill {pid}` before `-9`; only touch resources named `{project_name}` / `{project_org}/{internal_name}:*`; never broad prune commands; confirm before deleting user data, config, DB files, certs, or git repos.

**mkdocs.yml / .readthedocs.yaml:** Engine is MkDocs Material (dark/light/auto toggle, dark default), hosted on ReadTheDocs — URL format is whichever matches the actual RTD project dashboard: `https://{project_org}-{project_name}.readthedocs.io` (org-project), `https://{project_name}.readthedocs.io` (project-only), or a custom domain — never guessed. `mkdocs.yml` sets `site_name`, `repo_name: apimgr/vidveil`, Material theme + extensions (admonition, superfences/mermaid, tabbed, tasklist, magiclink with `user: apimgr, repo: vidveil`), `extra_css` for `stylesheets/dark.css`/`light.css`, and a `nav` covering Home/Installation/Configuration/API/CLI/Security/Integrations/Development. `.readthedocs.yaml` is `version: 2`, `build.os: ubuntu-24.04` (latest LTS), `tools.python` latest stable, `mkdocs.configuration: mkdocs.yml`, `python.install` from `docs/requirements.txt` (`mkdocs`, `mkdocs-material`, `mkdocs-minify-plugin`, `pymdown-extensions`).

**Required docs/ files:** `docs/` is the operator/user/integrator documentation set and MUST explain the shipped product as it actually behaves — browser, CLI, API, config, and any enabled public protocol/discovery surface (`.well-known/**`, Swagger/GraphQL docs, autodiscover, OAuth/OIDC metadata, native app association, security reporting). Generated OpenAPI/GraphQL output does not replace these prose pages. `index.md` (homepage + quick start), `installation.md` (Docker/binary/systemd), `configuration.md` (all settings), `api.md` (endpoints/formats), `cli.md` (if CLI exists), `security.md` (auth model, public/health endpoints, security reporting, well-known namespace), `integrations.md` (machine identity, autodiscovery, webhooks, federation, native app links — or "none enabled"), `development.md` (contributing guide), `requirements.txt`. Custom theme colors MAY override defaults but MUST keep WCAG AA 4.5:1 contrast in both themes and be documented in AI.md.

**I18N translation key conventions:** every human-readable string (web, API errors, Swagger/GraphQL descriptions, email, server/CLI/agent CLI output, health page, cookie consent, privacy/terms) uses `t(r, key)` / `{{t .Lang key}}` — no hardcoded text anywhere, no exceptions. Dot-separated lowercase keys (`health.status.title`), `{variable}` interpolation, plurals nested under CLDR categories (`zero/one/two/few/many/other`). Single source of truth: `src/common/i18n/locales/{lang}.json`, embedded in ALL binaries via `go:embed` — server and CLI always support identical languages/keys. Missing key → fall back to `en`; unsupported language → silently fall back to `en` (never error). Language resolution: web `?lang=` (sets 1-year cookie) → `lang` cookie → `Accept-Language` header → `en`; CLI/server/agent `--lang` flag → config file `lang:` → `LANG`/`LC_ALL` env → `en`. Locale integrity and translation placeholders are validated by the i18n package tests run with `make test`, per AI.md PART 30.

**Supported locales:** `en` (English, ltr, one/other), `es` (Spanish, ltr, one/other), `zh` (Chinese, ltr, other only), `fr` (French, ltr, one/other, 0="one"), `ar` (Arabic, **rtl**, zero/one/two/few/many/other), `de` (German, ltr, one/other), `ja` (Japanese, ltr, other only). Arabic requires `dir="rtl"` (from `meta.direction` in the locale file) and CSS logical properties (`margin-inline-start`, `text-align: start`, never physical `left`/`right`). Date/time/number/currency formatting via `golang.org/x/text`, locale-aware per language.

**Accessibility (a11y) baseline:** WCAG 2.1 AA mandatory — 4.5:1 contrast for normal text (3:1 for large text/UI components/focus indicators), full keyboard navigation, NVDA/JAWS/VoiceOver screen-reader support, visible focus indicators, 44×44px minimum touch targets. Skip links (`#main-content`, `#navigation`) as the first two focusable elements on every page. ARIA: `role="status"`/`aria-live="polite"` for status, `role="alert"`/`aria-live="assertive"` for errors, `role="dialog"` + `aria-modal="true"` + focus trap for modals, landmark roles (`banner`/`navigation`/`main`/`complementary`/`contentinfo`), `aria-required`/`aria-describedby`/`aria-invalid` on form fields. Focus management: modal open → first focusable inside; modal close → trigger element; toast → do NOT move focus, use `aria-live` instead. `.sr-only` class for screen-reader-only text; never rely on color alone to convey meaning. Test with axe DevTools, WAVE, Lighthouse, a screen reader, and keyboard-only navigation; automated integration tests must verify skip links, alt text, label association, heading hierarchy, and landmarks.
